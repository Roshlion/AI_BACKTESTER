# README.md

# AI Backtester (S3-First, Next.js 14)

Web-based, AI-powered strategy backtesting over historical market data stored as **Parquet** in **AWS S3**. The application features a modern three-tab interface for comprehensive trading strategy development and analysis.

## New Three-Tab Navigation

**Dashboard** (default): Multi-ticker selection with interactive charts, indicator configuration, and seamless handoff to Strategy Lab.

**Strategy Lab**: AI-powered strategy generation with natural language prompts, sector-based ticker selection, and comprehensive backtesting capabilities.

**Data Warehouse**: Comprehensive data exploration with filtering, searching, and metadata viewing for all available datasets.

## Key Features

### Dashboard
- **Multi-ticker selection**: Full-row highlight selection with search filtering
- **Eye icon deep linking**: Click the eye icon to view any ticker in the Data Warehouse
- **Isolate action**: Context menu to focus on a single ticker
- **Indicator configuration**: Toggle SMA/EMA with editable periods, RSI (14), and MACD (12,26,9)
- **Auto date range**: Automatically computes date range from selected tickers' data spans
- **Create strategy handoff**: Seamlessly switches to Strategy Lab with pre-filled context

### Strategy Lab (Manual-First with AI Autofill)
- **Manual Strategy Builder**: Build strategies manually using visual DSL/ML builders (no prompt required)
  - **DSL Builder**: Add/remove rule blocks (SMA/EMA cross, RSI thresholds, MACD crosses)
  - **ML Builder**: Select models (RandomForest, XGBoost, Neural Nets, etc.) and configure hyperparameters
  - **Code Editor**: Advanced Python code editing for custom ML strategies
- **Portfolio Settings Panel**: Configure position sizing, costs, risk controls, and rebalancing
  - Position sizing: fixed dollar, % of equity, or risk-based (ATR)
  - Costs: commissions (fixed + %), slippage (bps), short borrow rates
  - Risk controls: stop loss, take profit, max positions, max weight per ticker
  - Rebalancing: frequency and drift thresholds
- **"Generate with AI" Button**: Optional AI autofill that populates manual forms (doesn't auto-run)
  - Enter natural language prompt describing your strategy
  - AI fills DSL rules or ML model configuration
  - User can review and edit before running backtest
- **Portfolio-Aware Backtesting**: Full portfolio simulation with:
  - Multi-ticker support with accurate cash/position tracking
  - Realistic fees, slippage, and market impact
  - Risk metrics: Sharpe, Sortino, max drawdown, volatility, CAGR
  - Trade-by-trade ledger with P&L attribution
  - Equity curves, drawdown charts, and per-ticker performance
- **Dual Execution Modes**:
  - TypeScript DSL engine (default) for speed
  - Python DSL/ML engine (via `USE_PY_BACKTESTER=1`) for advanced features
- **Standalone operation**: Works independently when accessed directly without prefill

### Data Warehouse
- **Symbol-level pages**: Deep link support (e.g., `/explore?symbol=AAPL`) for detailed ticker views
- **Comprehensive filtering**: Search by ticker, sector, industry; date range filtering; sortable columns
- **Metadata exploration**: Records count, date ranges, file formats, sector classifications

### Chart Readability & Performance
- **Series management**: Click legend to hide/show individual tickers; hover for emphasis
- **Multi-scale support**: Price (absolute), Indexed % (normalized to 100), Small multiples (grid view)
- **Indicator panels**: RSI and MACD in separate sub-panels with reference lines
- **Performance optimization**: Automatic downsampling for >5k data points
- **Error boundaries**: Graceful handling of missing data for selected symbols

## Architecture Overview & Deployments

### System Components

**Frontend (Vercel)**
- Next.js 14 App Router deployed on Vercel
- Three-tab interface: Dashboard / Strategy Lab / Data Warehouse
- Consumes `ML_API_URL` for ML strategy generation and backtesting
- Health monitoring via `/api/ml/health` proxy to ML service

**Python Service (Docker / AWS App Runner)**
- FastAPI application running on port 8081
- Docker image can run locally or deployed to Amazon ECR/App Runner
- Reads per-symbol Parquet files from S3 via HTTPS (`S3_BASE`)
- Endpoints:
  - `GET /health` — Health check
  - `POST /backtest/dsl` — DSL-based backtesting with portfolio simulation
  - `POST /ml/train-predict` — ML model training and prediction with portfolio simulation
- Portfolio simulator applies position sizing, fees, slippage, stops, and rebalancing
- Instance role (cloud) or IAM credentials (local) provides S3 read access

**Data Storage (AWS S3)**
- Bucket: `ai-backtester-data-rosh`
- Prefix: `prod/`
- Layout: Per-symbol Parquet files (`AAPL.parquet`, `MSFT.parquet`, etc.)
- Manifest: `index.json` generated by `build-manifest.ts`

### Environment Configuration

**Frontend (Vercel / local `.env.local`)**
```
NEXT_PUBLIC_APP_URL=http://localhost:3000
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini

```

**Python Service (Local / App Runner Environment Variables)**
```

AWS_REGION=us-east-1
AWS_ACCESS_KEY_ID=...  (local only; App Runner uses instance role)
AWS_SECRET_ACCESS_KEY=...  (local only)
```

### Quickstart: Run Python Service Locally

1. **Start Python service with Docker Compose**
   ```bash
   # Copy .env.local to .env (docker-compose will use it)
   cp .env.local .env

   # Start services
   docker-compose up python-service

   # Health check
   curl http://localhost:8081/health
   ```

2. **Or run Python service directly**
   ```bash
   cd python-service
   pip install -r requirements.txt
   export S3_BASE=https://ai-backtester-data-rosh.s3.amazonaws.com/prod
   uvicorn app.main:app --host 0.0.0.0 --port 8081
   ```

3. **Run tests**
   ```bash
   # TypeScript tests
   npm run test

   # Python tests
   cd python-service
   pytest
   ```

### Deploy Python Service to AWS

1. **Build and push Docker image to ECR**
   ```bash
   cd python-service
   docker build -t ai-backtester-py:latest .
   docker tag ai-backtester-py:latest <ACCOUNT>.dkr.ecr.us-east-1.amazonaws.com/ai-backtester-py:latest
   docker push <ACCOUNT>.dkr.ecr.us-east-1.amazonaws.com/ai-backtester-py:latest
   ```

2. **Create App Runner service**
   - Container image URI: `<ACCOUNT>.dkr.ecr.us-east-1.amazonaws.com/ai-backtester-py:latest`
   - Port: 8081
   - Health check: `/health`
   - **Instance role**: Attach `AmazonS3ReadOnlyAccess` policy
   - **Environment variables**: Set `S3_BASE`, `AWS_REGION`

3. **Configure Vercel**
   - Add environment variable: `ML_API_URL=https://<apprunner-service-url>`
   - Optionally set: `USE_PY_BACKTESTER=1` to use Python for DSL execution
   - Redeploy frontend

## Technical Stack

- Frontend: Next.js 14 (App Router, RSC), TailwindCSS, Recharts
- APIs (Node runtime):
    - GET `/api/health` — pings manifest in S3
    - GET `/api/index` — returns the S3 manifest (tickers, asOf, source)
    - GET `/api/local-data?ticker=XYZ&start=YYYY-MM-DD&end=YYYY-MM-DD` — returns normalized OHLCV rows
    - GET `/api/ml/health` — proxies ML service health check
    - POST `/api/strategy/generate` — `{ prompt } → { dsl }` using OpenAI
    - POST `/api/strategy/run` — executes `{ mode: "dsl" | "ml", dsl | code, tickers, startDate, endDate }`
- Libraries:
    - `lib/env.ts` — strict env loader (AWS_BUCKET, AWS_REGION, AWS_PREFIX, S3_BASE, OPENAI_*)
    - `lib/*` — ingestion/parquet fetch + strategy engine (indicators + backtest loop)
- Scripts:
    - `scripts/build-manifest.ts` — walks `s3://bucket/prefix/` and writes `index.json` (no ACLs)

4. Adjust portfolio settings as needed
5. **Run Backtest**

## Developer Notes

### App Router Page Exports
- All `app/**/page.tsx` files must only export allowed Next.js exports: `default`, `generateMetadata`, `generateStaticParams`, `revalidate`, `dynamic`, `dynamicParams`, `fetchCache`, `runtime`, `preferredRegion`, `maxDuration`, `metadata`
- Helper functions must be moved to `utils.ts` files in the same directory
- Use `npm run check-page-exports` or `node scripts/check-page-exports.js` to validate compliance

### Strategy Page Server→Client Pattern
- `app/(shell)/strategy/page.tsx` is a Server Component that parses `searchParams` and passes values to `StrategyClient` wrapped in `<Suspense>`
- `StrategyClient.tsx` is a Client Component that renders the Strategy Lab UI
- Uses `dynamic='force-dynamic'` and `revalidate=0` for fresh data on each request

### Global State Handoff
- Zustand store in `app/store/strategyStore.ts` manages strategy handoff between Dashboard and Strategy Lab
- Dashboard calls `setStrategy()` with tickers, indicators, and date range, then navigates to `/strategy`
- Strategy Lab reads from URL params if present, otherwise falls back to store values

## Troubleshooting

### Strategy Lab Issues

- **400 Error: "tickers array required"**
  Cause: DSL/ML run endpoints expect `tickers: string[]` in request body.
  Fix: Ensure Strategy Lab always sends tickers array (never single string).

- **ML service offline / 501 Error**
  Cause: `ML_API_URL` not set or ML service unreachable.
  Fix:
    - Check `ML_API_URL` is set in Vercel environment variables
    - Verify App Runner service is running and health check passes
    - Check CORS configuration if ML service blocks requests

- **CORS errors with ML service**
  Cause: ML service rejecting frontend origin.
  Fix: Set `CORS_ORIGINS=https://your-vercel-domain.vercel.app` in App Runner environment variables.

- **Generate buttons always disabled**
  Cause: Manual Checker mode is enabled.
  Fix: Toggle off "Manual checker" switch in Strategy Lab header.

- **Loading state stuck / buttons disabled**
  Cause: Previous async action failed without cleanup.
  Fix: Refresh page; check browser console for errors; verify API endpoints respond correctly.

### Build & Deployment Issues

- **Vercel build error: "stream did not contain valid UTF-8" for `app/.../page.tsx`**
  Cause: files saved with non-UTF-8 or CRLF; fix by re-saving as UTF-8 LF and committing `.gitattributes`:
    - Ensure editor saves `app/dashboard/page.tsx` and `app/strategy/page.tsx` as **UTF-8 (LF)**.
    - Add `.gitattributes` line: `* text=auto eol=lf`
    - Commit and redeploy.

- **Charts flat at 0 for non-AAPL tickers**
  Most likely normalization gaps (schema variants, DECIMAL scales, BigInt). See `DOCUMENTATION.md` → Parquet normalization. Ensure the loader:
    - Maps aliases (open|o|OpenPrice, high|h|HighPrice, low|l|LowPrice, close|c|ClosePrice, volume|v|Volume)
    - Handles decimals (divide by 10^scale when applicable)
    - Converts BigInt/Int64 to JS number
    - Skips invalid rows rather than defaulting to 0

- **Missing env variables**
  App uses `.env.local` automatically. For manual CLI tests, export needed vars into the shell or sync from `.env.local`.
